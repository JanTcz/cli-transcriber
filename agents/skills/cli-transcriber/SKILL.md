# cli-transcriber

In this project skills and agents are written as YAML and generated into
Markdown. A generated file starts with
`<!-- Generated by cli-transcriber from <source>: ... -->`.

- **Edit the source, never the generated file.** It is rewritten on every
  build. The header names the source.
- **A new skill or agent is a new source**: `<name>.skill.yaml` or
  `<name>.agent.yaml` next to the others, not a new `SKILL.md`.
- **After every change run** `npx -y cli-transcriber@0 build` and fix every
  problem it reports (`file:line  error  message`) until it writes. Then
  `npx -y cli-transcriber@0 check` must pass. Never use `--force` unless the
  user asks: it overwrites files the tool didn't write.

## The sources

```yaml
# skills/review.skill.yaml (file name = name)
name: review
description: What it does and when to use it (agents read this to choose it).
imports:                      # everything the body uses, nothing it doesn't
  partials: [report]
  skills: [incident]
  agents: [security-check]
frontmatter:                  # extra frontmatter, e.g. allowed-tools (agents: tools, model)
  allowed-tools: Read, Grep
body: |                       # or prose_blocks: [{ placement: skill-intro, body: ... }]
  Hand it to {{agent:security-check}}; afterwards run {{skill:incident}}.

  {{partial:report title="Review"}}
```

```yaml
# partials/report.partial.yaml: text shared by several skills or agents
name: report
params:
  - name: title               # required unless it has a default
  - name: tone
    default: plain
body: |
  ## {{title}}
  Write it {{tone}}.
```

```yaml
# rules/leave-it-better.rule.yaml: a rule, often from a shared corpus; edit it there, not here
name: leave-it-better
title: Leave it better
severity: SHOULD              # title, severity, scope, version, status... are metadata
body: |                       # the only thing written out, as it is
  Leave every file in better shape than you found it.
```

A skill, agent or partial uses a rule with `imports: { rules: [leave-it-better] }`
and `{{rule:leave-it-better}}`, which becomes the rule's body and nothing else.

## Checks the build enforces

- Every `{{partial:…}}`, `{{rule:…}}`, `{{skill:…}}` and `{{agent:…}}` must exist and be
  listed under `imports`; everything under `imports` must be used.
- A partial call gives every parameter without a default, and only parameters
  the partial declares; a partial uses every parameter it declares.
- A partial or rule with several lines stands alone on its line (its indentation is kept).
- A rule has no imports or parameters; its body is text, its `{{` are not markers.
- Partials may use other partials (declared in their own `imports`), but not in a loop.
- Tools in `allowed-tools` / `tools` must be real tool names (or listed in
  `transcriber.yaml` under `tools`).
- `\{{` writes a literal `{{`.

## When the same text appears in two places

Move it into a partial and use `{{partial:name}}` in both, with parameters for
what differs. That is the point of the tool: one place to change it.
